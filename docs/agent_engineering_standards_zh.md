# Agent 通用工程规范

> 适用范围：Codex、Cursor、Claude Code 和其他 coding agent。  
> 目的：把跨项目通用的软件工程底线写成明确规则，减少大而乱的改动、隐式耦合和无法审查的提交。

## 1. 变更粒度

- 一次任务只解决一个清晰目标。
- 功能开发、bug 修复、重构、格式化、依赖升级、迁移和大规模删除尽量拆成独立提交。
- 大改造必须先有阶段计划；每个阶段都要保持项目可运行。
- 不把“顺手清理”混进功能提交，除非它是完成该功能的必要前置。

## 2. 模块解耦

- 新逻辑放在职责明确的模块内，不把业务逻辑散落在 CLI、控制器、UI、测试 fixture 或脚本里。
- 上层可以调用下层公开接口，下层不要反向依赖上层。
- 避免循环依赖、隐藏全局状态、隐式单例和跨模块直接修改内部数据。
- 配置、路径、凭据引用、运行环境差异放在配置层或启动层，不硬编码到核心逻辑。
- 公共接口要小而稳定；内部实现可以变化，但不要让调用方依赖内部字段或私有函数。

## 3. 文件、函数和复杂度

这些是软阈值，用于提醒 agent 主动评估拆分，不是机械行数竞赛：

```text
单文件超过约 500 行：检查是否可以按职责拆分。
单函数超过约 80 行：检查是否包含多个阶段、多个抽象层或重复分支。
单类同时负责 IO、业务规则、状态管理和展示：优先拆分。
嵌套层级超过 3 层：优先用提前返回、提取函数或表驱动逻辑降低复杂度。
同一段逻辑复制 3 次：提取公共函数、fixture、模板或数据驱动结构。
```

如果保留长文件或长函数更合理，最终说明中要解释原因。

## 4. 测试和验证

- 新增或修改业务逻辑必须补充或更新测试。
- 纯重构应由现有测试证明行为不变；如果关键路径没有测试，先补测试或说明风险。
- 测试应覆盖正常路径、边界输入、空数据、错误路径和关键回归。
- 不为了让测试通过而弱化断言、删除失败用例或跳过关键检查。
- 验证命令必须写入最终回复；失败或未运行要写明原因。

## 5. 契约和兼容

- 公共 API、CLI 参数、配置 key、环境变量、数据 schema、数据库表和文件格式变更必须同步调用方、测试和文档。
- 删除或替换行为时，不保留半新半旧的实现；如果需要兼容层，要说明生命周期。
- 错误信息、返回值、状态码和数据字段属于契约的一部分，不能随意改变。

## 6. 错误处理和可观测性

- 不吞异常，不用宽泛 `except` 隐藏失败。
- 错误信息要包含足够上下文，但不得泄露凭据、token、cookie 或敏感数据。
- 网络、文件、数据库和外部 API 调用要考虑超时、空响应、重试、幂等和部分失败。
- 日志用于定位问题，不用于堆砌噪声。

## 7. 安全和数据边界

- 不提交 `.env`、API key、cookie、密码、token、私钥、供应商凭据或付费数据导出。
- 不把真实凭据写进 Markdown、测试 fixture、示例配置或聊天记录。
- 本地运行数据、缓存、数据库、模型产物和生成报告默认不进 git，除非项目明确要求。
- 处理用户数据、生产数据和第三方数据时，先确认授权边界。

## 8. 文档和项目记忆

- 用户需要直接运行的命令必须写进 README 或项目指定文档。
- 架构边界、长期决策、数据口径和运维策略写入项目决策文档，不依赖聊天记录。
- 每次较大改动结束时，更新项目状态或 agent journal，记录完成项、验证结果和下一步。

## 9. Git 和提交

- 提交前运行 `git status --short`。
- 只 stage 本轮任务相关文件，禁止 `git add .`。
- 不提交用户或其他 agent 的无关改动。
- commit message 使用 Conventional Commits。
- 自动提交前必须完成验证；验证失败时不要提交。

## 10. 参考来源

这些规则参考并压缩自以下公开实践，按本仓库使用场景改写为中文执行项：

- Google Engineering Practices：小 CL、重构与功能拆分、测试同行、保持构建可用。  
  https://google.github.io/eng-practices/review/
- Google Python Style Guide：lint、导入、异常、全局状态、类型标注、函数长度不设硬上限但要求可读。  
  https://google.github.io/styleguide/pyguide.html
- Cursor Rules 官方文档：规则应聚焦、可执行、可拆分，项目规则放 `.cursor/rules`。  
  https://docs.cursor.com/en/context
- Claude Code memory/skills 文档：长期事实放 `CLAUDE.md`，流程型内容放 skill，规则要短而明确。  
  https://code.claude.com/docs/en/memory  
  https://code.claude.com/docs/en/skills
- Agent Skills 开放规范：使用 `SKILL.md` 和渐进加载，减少上下文成本。  
  https://agentskills.io/specification
- Conventional Commits：提交信息使用机器和人都能读懂的结构。  
  https://www.conventionalcommits.org/en/v1.0.0/
